# Автоматизация отчётности по продажам (RetailPoint)

## 📌 Описание проекта
Программа предназначена для автоматического сбора, очистки и анализа данных о продажах из CSV-файлов разных торговых точек. Разработана в строгом соответствии с требованиями заказчика с использованием только стандартной библиотеки Python (без сторонних зависимостей вроде pandas).

## 🚀 Инструкция по запуску
1. Убедитесь, что у вас установлен **Python 3.11+**.
2. Поместите исходные CSV-файлы с отчетами магазинов в папку `data` (по умолчанию программа ищет файлы в `./data`).
3. Запустите скрипт из корневой папки проекта:
   ```bash
   python main.py
   ```

## 📁 Результаты работы
После успешного выполнения программы формируются следующие файлы:
*   `reports/sales_report.csv` — итоговый отчет с агрегированными данными по товарам и общей выручкой компании.
*   `reports/errors.log` — текстовый лог, содержащий информацию о пропущенных строках, сгруппированных по причинам пропуска.

## 🛠 Принятые технические решения и архитектура

Проект реализован с использованием **слоистой архитектуры**. Код разделен на логические модули в папке `src/`, что обеспечивает слабую связанность, высокую надежность и легкость поддержки:

*   **`src/io/` (Ввод-вывод):** Модули `receiving`, `assembly`, `report`. Отвечают за поиск файлов, их чтение и сохранение итогового отчета. Не содержат бизнес-логики.
*   **`src/processing/` (Обработка):** Модули `check`, `cleaning`, `grouping`. Отвечают за валидацию структуры файлов, очистку данных от некорректных значений и группировку продаж.
*   **`src/core/` (Ядро):** Модуль `calculations`. Содержит чистую математику и бизнес-логику (расчет сумм, поиск лидера).
*   **`src/services/` (Сервисы):** Модуль `errors`. Централизованно собирает, форматирует и сохраняет лог ошибок.
*   **`main.py`:** Точка входа. Выступает в роли дирижера, связывая все модули между собой в правильной последовательности.

## ⚠️ Правила обработки ошибок (Data Cleaning)

Программа спроектирована так, чтобы быть устойчивой к поврежденным или некорректным данным. Ошибка в одной строке не останавливает обработку остальных файлов. 

**На уровне файлов:**
*   Пустые файлы или файлы, не содержащие обязательных колонок (`product`, `quantity`, `price`), пропускаются целиком.

**На уровне строк (строка удаляется, если):**
1.  **Пустые значения:** Хотя бы одно из полей (`product`, `quantity`, `price`) пустое или состоит из пробелов.
2.  **Некорректные числа:** В полях `quantity` или `price` записан текст (например, `"two"` или `"seventy"`).
3.  **Отрицательные значения или ноль:** Если `quantity <= 0` или `price <= 0`. Считается, что продажа не может быть отрицательной или бесплатной.

Все отброшенные строки, их исходные данные и конкретные причины пропуска фиксируются в консоли и в файле `reports/errors.log` для прозрачности отчетности.
